# 撕开素材层路线（kraft-tear）

> 定位：photo-cutout-forge 的**素材驱动背景**路线——整幅背景素材图（岩壁／石面／纸等，随用户上传素材自适应），
> 上下撕口沿主体轮廓弧撕开，中缝露出一条内容；**素材层始终压在内容之上**（先背景、后文字铁律不变）。
> 脚本：`scripts\kraft_tear.py`（A）／`scripts\kraft_photo.py`（B）／`scripts\textzone_glow.py`（深底排字护读）。

## 0 输入模型（三输入）与合成顺序（不可换）

三输入：①一张**含主体物的实拍素材**（`--photo`，B 路线窗口用；抠出 `--cutout` 供撕口轮廓弧）
＋②一张**材质素材图**（`--material`，背景纹理，色调/质感越贴近主体环境越契合）
＋③一段**对主体物的描述**——写进白底候选的图生图提示词（改写规则见 `cutout-craft.md` §①；
描述影响轮廓带形态与高度，进而影响撕口窗口，见 §4）。

```
整幅素材层 → 窗口内容（A 抠图主体 / B 实拍原图）→ 撕口轻投影（窄带 7px/0.24，保内容原色）
  → 上素材 over（y≤e_top）→ 下素材 over（y≥e_bot）→ 纸芯白线 5px＋纸边微高光 0.10
```

撕口几何：撕口线 = 主体轮廓弧 × k（压缩系数，k<1 更平缓）＋随机撕边；
压边自动定位：素材边最少压住主体 20px（主体边缘始终藏在素材后）。

## 1 两条窗口内容路线（选谁）

| 路线 | 脚本 | 窗口内容 | 结论 |
|---|---|---|---|
| A | `kraft_tear.py` | 抠图主体 | 弧与轮廓之间必然夹出素材色（k<1 的结构性问题）；软边收硬后主体原色恢复，但窗口仍非完全连续 |
| **B（推荐）** | `kraft_photo.py` | 实拍原图 | 窗口内是连续实拍画面，无素材色混入；敦煌定稿走此路线 |

两脚本同 `--seed` 输出几何完全一致（敦煌案例 @ k=0.60 / zoom 1.45 / seed 33：e_top≈539、e_bot≈1025、tuck 20/20）。
旧参数默认路径已与 v3r 定版逐字节对齐（smoke 实测 md5 一致，新参数默认零回归）。

### 1.5 轮廓源：AI 剪影 vs 照片描线 mask（撕口「像不像主体」的命门）

撕口线＝`--cutout` 剪影的轮廓弧，剪影从哪来有两条路：

| 轮廓源 | 适用 | 做法 |
|---|---|---|
| ① AI 剪影候选（默认） | 主体几何与实拍基本一致（正对／单翼） | 白底候选 → `cutout.py` → 直接喂 `--cutout` |
| ② **照片描线 mask**（保真） | AI 剪影几何与实拍**不符**（多翼、U 形透视、斜视） | 照片上按真实边界描 top/bot 控制点 → 折线 → **与照片同尺寸**的 alpha 带状 mask → 喂 `--cutout` |

- 换线判据：渲染后窗口底落进地板行／窗口顶露天花，且 `--k / --wall-top-row / --zoom` 怎么调都对不上两翼与中段——
  剪影的比例与实拍透视不同（案例实测：AI 剪影中段下压幅度≈实拍几何 2 倍）。
- 描线做法（案例 `skill-test-gallery-tear`）：照片叠加格网目视测量（墙面 S≈0.10-0.25 低饱和、木地板 S≥0.3；
  亮度受聚光/暗带干扰，须 L+S 联合判读）；控制点分别描「左墙顶→中段远处墙顶→右墙顶」三段顶线与对应的墙脚线；
  `np.interp` 生成折线，`(yy>=top)&(yy<=bot)` 填 alpha → 与照片同尺寸的 mask。
- 描线参数：`--wall-top-row` = 描线 top 均值（照片行）；`--k 1.0`（撕口线＝描线 ±tear，不再压缩）；
  `--smooth 21`（保轮廓细节——默认 81 会把折线磨成大波浪）。
- ★ 案例：**三面幕墙（左中右 U 形）**，2026-10-12 case17 —— 完全按上面这条走：
  叠格网目视读出「三段顶线 ＋ 墙脚线」→ `np.interp` 折线 → 与照片同尺寸 alpha mask
  → `torn_edge.py`（撕裂）→ `kraft_photo.py --k 1.0 --smooth 21`。
  实测数值：照片 1537×1920，顶线均值 371、墙脚均值 1099、带高均值 728（覆盖 37.9%）；
  `--wall-top-row 371 --top-edge 420 --yA 420`（⚠ 这两个参数一个管照片落位、一个管撕口线位置，
  **必须同时给且一致**，只给一个会整体错位 ~120px）。
- ⚠⚠ **透视收缩的两侧展墙：中段"墙顶"比眼睛看到的位置低得多**（2026-10-12 case04 实测）。
  画面左边近处墙顶在照片 y≈640，中段远处墙顶在 y≈**900**，右边又升到 y≈370 ——
  只凭「天花/墙交界那道边」目视，会在中段把它读高 ~150px，撕口上缘就吃进灰幕/天花。
  **可靠做法：逐列打竖直像素剖面**（`x` 固定，从 y 上往下打印 RGB，找「暗幕→亮墙」的跃变），
  再抽 8–10 个 x 的值做控制点；局部放大叠 50px 网格只用来复核、不用来读绝对位置。
  中段远景带天生很窄（案例中带高只剩 ~190px），**不要**为了"带宽好看"把上缘抬到墙顶之上 ——
  要么接受窄腰（哑铃形），要么把下缘截在墙脚之上（**绝不露地板**，用户明确要求）。
- 验证（数值审计）：B 路线窗口内容＝照片切片 **1:1** 铺入——逐列比对渲染图与照片像素，取**最长匹配游程**＝实际窗口上下界；
  合格线：窗口顶＝描线 ±10px（照片行）、窗口底＝墙脚线**之上**约 100 行（不露地板）。

### 1.6 撕口取形：一字型还是哑铃形（2026-10-11 组员反馈后补）

**撕口线的形状 ＝ mask 上下缘 × k**，所以**取形就是选 mask 的形状**。
用 `scripts\band_mask.py` 生成，内置两个预设：

| 形态 | 特征 | 效果 |
|---|---|---|
| `flat` | 一字型横带，上下缘几乎平直 | 稳、干净；但**容易把画面切成上／中／下三等分**，生硬割裂 |
| `pinch` | **中间凹陷、两端扩张**（哑铃形） | 中缝中间窄、两端宽，露出的内容有呼吸变化，**层次感强** |

组员反馈原话：「抠图会把原图抠出一条横平的"一"字型图案，导致画面很割裂，成为三等分的生硬情况」。

```powershell
python scripts\band_mask.py --w 1537 --h 1920 --shape pinch --out out\mask.png
python scripts\kraft_photo.py --cutout out\mask.png --photo src\scene.jpg --material src\material.jpg `
    --k 1.0 --smooth 21 --zoom 1.45 --wall-top-row 560 --material-gamma 0.52 --out out\bg.png
```

- ⚠ **`--smooth` 必须给 21**（不是默认 81）：默认值会把哑铃形磨成大波浪，取形白做。
- `pinch` 预设（画布高比例）：上缘 `0.252→0.332→0.258`、下缘 `0.552→0.476→0.546`
  （7 点，上下缘**故意不同**）。可用 `--top` / `--bottom` 传自定义控制点微调。
- **改完取形后中缝的上下缘位置会变** —— 所有「文字不压中缝」的检查阈值都要跟着重量
  （案例：中缝上缘由 539 → 左380／中583；下缘 1167 → 左1191／中990）。

### ⚠ 自然感：光给控制点不够（2026-10-11 老大反馈后补）

只给「中间凹」的控制点，做出来是**一条左右对称的光滑弧** —— 一看就是画出来的、
不像撕出来的（老大原话：「这种哑铃型又太过规整了，没有一种自然感」）。

真实撕口有三个特征，缺一不可：

| 特征 | 做法 |
|---|---|
| **不对称** | 上下缘用**不同形状**的控制点（不要镜像）；`band_mask.py` 会打印左右不对称量供检查 |
| **多尺度起伏** | `--jitter`（默认 0.012）叠加 **1D 分形噪声**：低频给大波形、高频给细碎边 |
| **边缘细碎** | 交给 `kraft_photo` 内建的随机 tear 补最后一点 |

```powershell
python scripts\band_mask.py --w 1537 --h 1920 --shape pinch --jitter 0.013 --seed 7 --out out\mask.png
```

- `--jitter 0` 关掉噪声、退回光滑弧（可做对照）；换 `--seed` 换一条撕口。
- ⚠ **噪声会抬高上缘、露出天花板**：`--jitter` 越大窗口上移越多，必须回头检查有没有露黑
  → 必要时把 `--wall-top-row` 调大（案例 560 → 600）。

**⚠ 这不写成死规则** —— 形态要按素材具体分析：

| 素材特征 | 建议 |
|---|---|
| 主体横向连贯、画面本身已有上下分区 | `flat` 更整齐 |
| 主体呈弧形／环抱，或需要打破三分感 | `pinch` 更有层次 |
| 中段内容本身就是主角（不想被"掐窄"） | 用 `flat`；或 `pinch` 但把中部起伏收小 |

> 取形是**版面判断**，不是参数默认值。**先看素材再决定**，别机械套 `pinch`。

### 1.7 取形方向：横向撕口带 还是 **竖向不规则开窗**（2026-10-11 加）

前面 §1.6 讲的都是**横向**取形（mask 的每列上下缘 → 一条横带），画面因此被分成上／中／下。
但有些素材的主体**天生是竖向一团**，横着切就会把它切成两截。

| 主体形态 | 取形方向 | 脚本 |
|---|---|---|
| 横向一片：墙面、长卷、横跨的纱幕、一带山峦 | 横向撕口带 | `band_mask --orient h` → `kraft_photo.py` |
| **竖向一团：展示柜、立像、器物、单个投影、一柱纹样** | **竖向不规则开窗** | `band_mask --orient v` → **`kraft_window.py`** |

```powershell
# 竖向开窗（case16 展示柜定稿参数）
python scripts\band_mask.py --w 1500 --h 1875 --orient v --shape vpatch `
    --jitter 0.008 --seed 11 --yspan 0.24,0.78 --out cut\win.png
python scripts\kraft_window.py --win cut\win.png --photo src\scene_clean.png `
    --material src\material.jpg --scale 2.13 --focus 0.617,0.50 `
    --material-gamma 0.52 --shadow 0.30 --rim 0.16 --out out\bg.png
```

- `--yspan` 限纵向范围（不给＝贯穿全高）；窗口**上下端也做不规则收口**（`--end-jitter`）。
  ⚠ **窗口长宽比要和照片里主体区域的长宽比匹配**，否则要么放不满（留空）、要么把主体裁掉：
  先量主体在照片里的 bbox，再定 `--yspan` 与 `--scale`（`scale ≈ 窗宽 ÷ 主体区宽`）。
  案例：主体区 282×422 px → 窗 601×1070 → scale 2.13（照片只有 707×470，2.13× 是上限附近，
  再大就糊）。
- `--focus` 是「照片里哪一点对准窗口质心」（0..1 相对坐标），用来把主体推到窗口正中。
- `--shadow`（洞口内投影）与 `--rim`（洞口外亮边）让窗口**不像贴上去的**；
  没有这两项时照片会像一张平贴的矩形。

### ⚠ 两条实测坑（2026-10-11 同日踩）

1. **坐标系统一**：`pa` 是**已放大**的照片，画布坐标减落点即可；
   第一版我多除了一次 `scale`（把画布换算成原图像素后又拿去索引放大图），
   结果窗口显示的是照片的**另一片区域**（画面里完全没有主体）。
   **症状很迷惑**：背景看着"正常"，只是内容不对 —— 必须对着素材核对窗口里是什么。
2. **截图类素材带彩色边框**：本案源 PNG 的**上边与左边各 2px 是纯蓝 (13,153,255)**（截图工具伪影）。
   `kraft_window` 的**边缘钳制**会把它复制成整条色带（窗口顶部一条蓝边）。
   → 落图前先做素材净化：`crop((2,2,w-2,h-2))`，并在日志里打印。

### 1.8 ★ 斜向不规则块：把整张海报「劈开」（2026-10-11 老大第二轮反馈后加）

**老大的话**：「不能扣出像模板那样的**从右上到左下方**竖向不规则图案吗？你这种矩形放在海报里太滑稽了，
模板里把整张海报分开的状态会更震撼。」

轴对齐的竖向开窗（§1.7）贴在画面里就是个「矩形贴片」；参考海报的震撼来自**一条斜贯全幅的不规则块**。

```powershell
# 斜向取形（case16 定稿）：两端宽、中间收腰 → 右上角一大块 / 中央收窄 / 左下角一大块
python scripts\band_mask.py --w 1500 --h 1875 --shape diag-pinch --rotate 38 `
    --jitter 0.010 --seed 5 --out cut\win.png
python scripts\kraft_window.py --win cut\win.png --photo src\scene_big.png `
    --material src\material.jpg --scale 1.0 --focus 0.600,0.545 `
    --material-gamma 0.52 --shadow 0.28 --rim 0.15 --out out\bg.png
```

**做法**：在「对角线长度的正方画布」上按横向带生成 → `PIL.rotate`（**逆时针为正**，`38` 得到
「右上→左下」）→ 中心裁回 W×H。`--jitter` / `--yspan` 语义不变。

**三条实测判据（都是量出来的）**：

| 项 | 结论 |
|---|---|
| **方向自证** | 脚本会打印**四角覆盖率**：`--rotate 38` → 左上 0%／右上 100%／左下 100%／右下 0% ✓（要的就是这个；`-38` 会反过来） |
| **腰宽定档** | 腰宽 **0.62D → 覆盖 56.5%**，中央没纸面、文字无处可放；**0.10D → 覆盖 39.2%**，左上＋右下各得一块纸面 ✓；但 **0.10D 的腰只有 200px，会把主体拦腰截断** → 本案取 **≈0.13D（315px）** |
| **文字落点** | 打印 6×6 覆盖网格（见案例 `run_case16.py`）：斜块占住右上＋左下，**文字全部放左上与右下角的纸面**，用「文字压窗口」检查（>2% 判压）逐元素核对 |

#### ⚠⚠ 破对称：别让上下缘互为镜像（2026-10-11 老大反馈）

第一版 `diag-pinch` 的控制点是**严格镜像**的（`bottom = 1 − top`：0.19/0.81、0.28/0.72…），
做出来是一条**中心对称的沙漏** —— 老大原话：「抠图**太过中心对称**了，图案可以更不规则一点」。
镜像控制点的数学特征：脚本打印的「不对称量」为 **0**（它就是查这个的）。

破对称要**三处一起动**（预设 `diag-rag` 已实现）：

| 手法 | 做法 | 本案取值 |
|---|---|---|
| ① **腰位偏心** | 最细处不在正中 | 3/6 处 0.125D、2/6 处 0.165D |
| ② **两端不等宽** | 两头的厚度不同 | 左端 0.755D ／ 右端 0.640D |
| ③ **腰深不同** | 上下缘下探／上拱的程度不一样 | 上缘下探到 0.445、下缘上拱到 0.570 |
| ④ 噪声更粗 | `--jitter` 提到 0.014–0.016 | 0.016 |
| ⑤ 角度不走整数 | 避免"刚好 45°"的规整感 | **41°**（34°／30° 会让左下角只覆盖 94%／80%） |

判据：脚本打印的**不对称量**应从 0 跳到 200–450px 量级。

**⚠ 腰变细的代价**：腰太细时**主体会被拦腰截断**（本案展示柜）。
处置不是把腰收回去，而是**把主体移到更宽的那一叶**（`--focus` 调 0.42,0.60 让主体落进上右叶）。

**⚠ 斜向版的三个连带约束**：

1. **窗口贯穿整幅对角线 → 照片必须铺满整张画布**（`scale ≈ 4`，源图 707px 宽会被放得发糊）
   → 先 `LANCZOS` 放大 ＋ `UnsharpMask` 预处理成 `scene_big.png`，脚本用 `--scale 1.0`。
2. **纸面区被压缩**：右下角只有 ~680px 宽 → 底栏必须改**单列**（两段并排会溢出画布，
   见下条），中文标题也改成**两条错落字柱**（学参考的「敦煌 ｜ 博物展」）。
3. **⚠ 溢出画布是「静默」的**：`space-between` 行内容超宽时，flex 会把第二段推到**画布外**，
   落进 body 底色（`#17130E`）。**元素自己的 `overflowX` 仍是 false**，
   机检表现为 **`P5 = 0`、CR ≈ 1.14**（看起来像"材质太暗"，其实是画布外）。
   → 判据：**压窗口检查显示 0% 而机检 P5=0，就先量元素右缘是否超过 1500**。

### 1.9 ★★ 自然感与质感：`torn_edge.py` ＋ 质感三件套（2026-10-11 老大反馈后加）

**老大的话**：「抠图图案**还是太规整了，缺乏自然感**。而且**抠图后缺乏质感**。」

#### 问题一：取形本质是「一维挤出」

`band_mask` 的横带是「每列一个上下缘」、竖窗是「每行一个左右缘」——即使叠了分形噪声，
仍是**一条光滑曲线＋抖动**，放大看就是"用刀切得有波浪"。**真实的撕裂在三个尺度上同时不规则**：

| 尺度 | 现象 | 做法（`torn_edge.py`） |
|---|---|---|
| 大（数十 px） | 缺口、鼓包，形状整体走偏 | **2D 分形噪声沿法向位移边界**（`--edge`） |
| 中（数～数十 px） | 一块块**被咬掉**的碎口 | `--bites` 个**随机椭圆**咬痕，**圆心放在外侧**沿外法向啃入 |
| 小（1–3 px） | **纤维毛边**：半透明细丝伸进伸出 | `--fray` 高频噪声 → alpha 落在 0.3–0.9 的过渡带 |

```powershell
python scripts\band_mask.py --w 1500 --h 1875 --shape diag-rag --rotate 41 --jitter 0.016 `
    --seed 5 --smooth 61 --out cut\win.png
python scripts\torn_edge.py --mask cut\win.png --out cut\win.torn.png `
    --edge 0.016 --bites 9 --bite-size 0.050 --fray 0.55 --fray-px 3.0 --seed 3
```

实测：覆盖 43.1% ｜ **毛边过渡带占 2.17% 像素**（不做撕裂时是 0%）。
调节手感：想更"烂"就同时加大 `--edge / --bites / --bite-size / --fray`；想干净就都调小或设 0。

#### ⚠ 两个必须避开的坑（都实测踩过）

| 坑 | 症状 | 处置 |
|---|---|---|
| **位移不做边界约束** | 把噪声加到整张图上 → 实心区里噪声低于阈值 → **画面中间一排白麻点** | 只在 `abs(ramp−0.5) < 0.34` 的**坡带内**允许翻边 |
| **咬痕圆心取在边界上／偏移方向反了** | 画面中央出现一个个**浮空的材质圆斑** | 圆心必须沿**外法向**推到外侧（`r × depth`），咬口才与外缘连通成凹缺；咬痕用**随机椭圆**（长宽比与朝向都随机），正圆会咬出一排同款圆缺、反而规整 |

#### 问题二：质感来自「照片和纸发生关系」

`kraft_window.py` 加**质感三件套**（默认开启，可调 0 关闭）：

| 开关 | 做法 | 效果 |
|---|---|---|
| `--seam 0.42` | 紧贴边缘的一条**窄暗环** | 材质像"压"在照片上（纸的厚度） |
| `--fiber 0.55` | 材质的**高频细节**沿边缘外侧盖到照片上 | 撕口纤维搭在画面上 |
| `--grain 0.30` | 让窗口里的照片吃进材质的**低频明暗 ＋ 细颗粒** | 照片像"印在同一张纸上"，不是贴上去的一张图 |

> ★ 配套改动：`kraft_window` 的窗口 alpha 改为**保留连续值**（原先 `> 0.45` 二值化，
> 会把 `torn_edge` 生成的毛边过渡带**整条丢掉** —— 这是"没有质感"的直接原因）。

#### ⚠⚠ 但 `--bites` 不适合长横带（2026-10-12 实测）

咬痕是**从外侧沿外法向啃入的随机椭圆**——在**近满幅长**的边界上，它读成**一排圆弧／扇贝边**，
不像"被咬掉一块"，像"用圆模打的孔"：

| 参数组 | 实测观感 |
|---|---|
| `--bites 18 --bite-size 0.030` | 整条边像**云朵边**，最糟（痕小又多，密集成波浪） |
| `--bites 10 --bite-size 0.045` | 留下 2–3 处**明显圆缺**，可接受但不自然 |
| **`--bites 0 --edge 0.017 --edge-scale 22 --fray 0.60 --fray-px 3.2`** | ✅ **最像手撕**：连续的不规则起伏＋细碎纤维，无圆孔 |

→ **横带取形默认 `--bites 0`**，把不规则性全部交给「2D 分形位移 ＋ 纤维毛边」；
咬痕留给**短边界**（竖向开窗／斜向块），那里圆缺读起来像"撕掉一块"。
比选时直接拼板看撕口条带（`board.py`，裁画布 y 430..640 那条），别在整幅上猜。

### 1.10 ★★ 第四条路线：满幅铺底（`kraft_full.py`，2026-10-12 加）

**老大的话**：「尽可能让海报**铺满**，像这几张一样」（参考 06 竹编艺术／07 徽州灯彩／13 非遗纸版）。
前三条路线都在**开一块口子**；这一条反过来——**照片直接铺满整张画布**，文字压在照片上。

```powershell
python scripts\kraft_full.py --photo src\scene.png --material src\material.jpg --out out\bg.png `
    --focus 0.50,0.52 --overlay 0.42 --vignette 0.30 --tone 0.16 --grain 0.22 `
    --scrim "50,80,790,1460,0.57,230; 1080,100,1500,1060,0.56,260; 0,1360,1500,1875,0.34,150; 980,50,1500,225,0.50,150"
```

三件事：① 照片 cover 铺满（`--focus` 取景）；② **材质当纸纹**（高频细节 ＋ 低频明暗按
`--overlay` 叠上）——和另外三条路线是同一种质感语言；③ 四缘压暗 ＋ `--tone` 向材质色偏。

#### ⚠⚠ 核心坑：满幅时照片明暗**不可控**，浅色字必挂 → 必须做「文字区 scrim」

参考 06/07 能压浅字，是因为**那块底子本来就暗**；而本案左上幕墙实测 **P95 = 158（WCAG 线亮度）**，
浅字 CR 只有 **1.31**、深字 3.03 —— **两头都不达标**。
`--scrim "x0,y0,x1,y1,强度,羽化px;…"` 把文字所在的那几块压下去：

| 判据 | 数值 |
|---|---|
| 浅字（#F2E9D8，L≈0.83）要达 4.5:1 | 底子的 **P95 必须 ≤ 37**（线亮度；≈ sRGB 105） |
| 本案落地 | 左带 0.57 ／ 右带 0.56 ／ 底带 0.34 ／ 右上角 0.50 |

配套两条实测：

1. **浅字模式要逐个元素改色**：基类里 `.col-sub／.col-tag／.mini／.org` 都写死了 `--ink/--ink-2`，
   只改 `.type` 的 color 会被盖掉（实测 CR 掉到 1.03）。母版 `body[data-full]` 里逐个覆盖。
2. **scrim 的羽化要够大**，否则画面里出现**一个暗矩形**（实测 140px 时 EN 版右侧一眼可见 →
   加到 230–260px 才化开）。
3. **先用实测扫位置，再放字**：本案 EN 小标签从 y980／1120 试到 **y840**
   （那一带是全图最暗处，CR 6.78），一次量出来比反复挪省事。

### 1.11 ★★ 取形方向与脚本解耦：**横向撕口带也能用 `kraft_window.py`**（2026-10-12 加）

上面 §1.7 把 `kraft_window.py` 写成「竖向开窗专用」，但它的机制其实是**取向无关**的：
`--win` 只取 alpha、照片按 `--scale`／`--focus` 落位 —— **横向撕口带同样能用它**，而且它独有**横向选景**。

| 脚本 | 照片落位 | 横向选景 | 适合 |
|---|---|---|---|
| `kraft_photo.py` | `by = --top-edge − --wall-top-row × sc`（mask **上缘均值**锚到 `--yA`） | ✗ 只能**居中裁两侧**（`--zoom`） | 主体大致居中、左右没有要排除的东西 |
| **`kraft_window.py`** | `ox = cx − fx·pw·sc`，`oy = cy − fy·phh·sc`（`cx/cy` ＝ mask alpha 质心） | ✅ **`--focus` 任意定位** | 需要「照片里取哪一段」（含横向平移） |

**判据（案例 05 实测）**：照片左侧有一块巨型鎏金标题面板，字与海报标题重复、被撕口切一半就成错字。
`kraft_photo` 用 `--zoom 1.0 / 1.15 / 2.0` 都排不掉它（居中裁天然留着左三分之一）；
换 `kraft_window --scale 1.0 --focus 0.56856,0.38531` 一次到位。

**算 `--focus` 的三步**（避免 §1.7 那条「重复除 scale」的坑）：

1. **读 mask 几何**：alpha>0.45 的**质心 (cx, cy)** ＋ 各列上下缘 → 得到窗口在画布上的实际范围
   （`band_mask` 是 1500×1875 与画布同尺寸时，mask 像素＝画布像素）；
2. **定照片落点**：`ox = 0 − 目标照片左缘 × sc`；`oy = 窗口上缘画布 y − 目标照片上缘 × sc`；
   `sc = 1500 ÷ 目标照片宽`（想把照片放大就先自己预处理，脚本用 `--scale 1.0`）；
3. **`--focus = (cx − ox)/(pw·sc), (cy − oy)/(phh·sc)`**。
   落位关系是 `canvas = photo + (ox, oy)`，即 `photo_y = canvas_y − oy` —— **不要再除一次 scale**。

**实测数值（案例 05）**：mask 质心 (752, 964)、外接 1499×992、覆盖 47.2%；
目标照片区 x476..1976 / y640..1592（已 2× 的 2160×2880）→ `ox −476`、`oy −146`
→ `--focus 0.56856,0.38531`（脚本回读落点 `(-476, -146)`，逐点比色一致）。

> ⚠⚠ **两条脚本对 mask 的锚定方式不同**（这是最容易踩的一处）：
> `kraft_photo` 只吃 mask 的**形状与带高**——它把上缘**均值**锚到 `--yA`，mask 画在哪一行无所谓；
> `kraft_window` **直接吃 mask 的绝对 alpha**——`band_mask` 控制点给的比例就是画布位置。
> 同一张 mask 喂两条脚本，窗口落点会差一截 —— **这是设计，不是 bug**；改控制点时先想清楚走哪条。

> ★ **取景前先把素材放大**：本案源图仅 1080×1440，而窗口要 1500px 宽（2× 以上插值）
> → 先 `LANCZOS` 2× ＋ `UnsharpMask(radius=2.0, percent=62, threshold=3)` 存 `scene.2x.png`，
> 脚本用 `--scale 1.0`，避免窗口内容发糊。

## 4 B 路线取景（--zoom / --wall-top-row）

- 口径：`--wall-top-row` = 照片中对齐到上撕口线（`--top-edge`，默认 539）的原图行；
  `--zoom` 同步放大轮廓与照片（>1 居中裁两侧），撕口窗口更高、主体画面占比更大。
- 敦煌定稿：`--zoom 1.45 --wall-top-row 1550` → 窗口 539..1025；照片行 1549..2487；
  sc = 1500×1.45÷照片宽（4202）≈ 0.518；可见照片 x337..1837、by -263。
- 步骤：
  1. 行亮度剖面定边界：照片中心带逐行求均值亮度 L（天花 L 低、壁画 L 高、地面 L 回落）；
  2. 渲染 2-3 个候选（旧 1250/1400/1550；z1.45 后定 1550）；
  3. 拼板目检：**顶部不露黑色天花、底部不露地面**（天花下界约 1550、壁画带到约 2600）。
- 失败特征：窗口顶缘露黑 → 增大 `--wall-top-row`；底缘露地面/前景物 → 减小。
- 窗口高度跟随主体轮廓带高（近正比，实测约 ×0.85）：主体描述让剪影更干净，但生图可能把主体带画得**更扁** →
  窗口变矮、露出内容变少。此情形用 `--zoom` 补偿（轮廓与照片同步放大，窗口更高、主体占比更大、两侧裁切）。
  案例（skill-test-mural-tear）：A5 剪影 z1.0 窗口 563px（WTR235 → 照片行 235..1023，偏矮）→ z1.58 窗口 869px
  （WTR694 → 照片行 694..1464，含墙基不露地）；定稿 `--zoom 1.58 --wall-top-row 694`。

## 5 深底排字（墨字＋光晕）

- 素材底色深浅不一，一律墨字近黑系：`--ink #171009` / `--ink-2 #1F150A` / `--ink-3 #251A0D` / 标签 `--gold #271B0D`；
- 光晕（`textzone_glow.py`）：形状 `m = ss((y-cy)/fy) * (1-ss((x-cx)/fx))`（左下角）；
  增益 `g = (0.26/p5)^(1/2.4) - 1 + 0.005`，**p5 必须取 WCAG 线性亮度（0-1 口径）**——
  用 sRGB 0-255 会得到错误增益（实测踩坑）；案例 p5 0.139 → g 0.303；
- 机检口径：背景亮度取字框内**单像素 P5（深字）**；旧牛皮纸版近黑墨字＋光晕最低 label 4.76。

## 7 陷阱清单（实测）

- **重上色抹掉素材颜色**：`photo_cover` 把素材映射到指定两色阶——素材自带色斑/裂纹/矿物色会被替换
  （用户实测反馈「岩壁原有的颜色怎么给抹去了」）→ 保原色走 `--material-gain`（1.0 直出／1.2 提两成）或
  `--material-gamma`（幂曲线）。
- **暗斑字区机检挂**：字区背景亮度取**单像素 P5（深字）**——素材暗斑落入字区即挂；
  纯增益救不了（提亮会炸亮部/裁切），用幂曲线 γ0.52（风化岩壁实测：γ0.52 后 12/12，min 4.63）。
- **候选提示词字面化**：描述主体用「图带/条带」等字面形状词 → 生图把主体画成漂浮条带（白隙成孔），
  内孔率反升（实测 11.31% ＞ 无描述 10.19%）→ 改写为「一整面完整连续的…，不是条带/碎片，不切割不分离」（6.54%）；
  另注意描述后的轮廓带可能更扁、撕口窗口随之变矮（563 vs 891px）→ `--zoom` 补偿（案例 1.58 / WTR 694）。
- **AI 剪影几何与实拍不符（多翼/U 形）**：剪影的墙带比例≠实拍透视（案例实测中段下压≈2 倍）→ 中段窗口底落进
  地板行、翼部窗口顶露天花，`--k/--wall-top-row/--zoom` 怎么调都对不上 → 换**照片描线 mask**（§1.5）：
  撕口＝真实墙面几何±tear（用户反馈「只需要两边画廊，结果把中间的地面也加进来了」即此坑）。
- **压缩弧 k<1 在多翼场景丢轮廓**：k=0.6-0.8 把两翼到中段的落差压成「沙丘波浪」，主体轮廓感消失
  （用户反馈「不要太为边缘平滑丧失主体物轮廓」）→ 轮廓保真优先 `--k 1.0` ＋ `--smooth 21`，手撕感交给 tear(±10px)。
- 素材整张**镜像平铺**会出现对称蝶形/菱形伪影（接缝肉眼可见）→ 必须
  「整幅等比放大盖满＋素材原生尺度细部高通叠加」（`photo_native/photo_cover`＋`photo_detail`）。
- 抠图软边（alpha 0.1-0.4 宽过渡）在深色素材上透底成渗色泥斑 → alpha 收硬为
  `(m-0.42)/0.10` 窄过渡带（A 路线 `build()` 内固定）。
- **横带上 `--bites` 会打成圆孔**：椭圆咬痕在近满幅长的边界上读成一排扇贝边（`--bites 18` 像云朵边）
  → **横带取形 `--bites 0`**，不规则性交给 `--edge`／`--fray`；咬痕留给短边界（见 §1.9）。
- **横向带要横向选景时别硬用 `kraft_photo`**（只能居中裁）→ 换 `kraft_window --focus`（见 §1.11）；
  注意两条脚本对 mask 的锚定方式不同（一个锚上缘均值、一个用绝对 alpha）。
- **`kraft_window` 的 `--detail` 与 `kraft_photo` 不同量纲**：前者默认 0.06（≈无效果）、后者 4.0；
  图案纸做材质时 `kraft_window` 给 1.5–2.0。
- rng 序列：`paper(rng)` 必须始终先调用（即使有素材），否则撕口随机形状变化、无法复现定版。
- `np.arange(H, dtype=np.float32)` 必须用关键字（第二位置参数会被当 stop）；
  PIL F 模式不支持 GaussianBlur（先转 uint8）；PowerShell 串联用 `;`；board.py 标签避免「·」。
