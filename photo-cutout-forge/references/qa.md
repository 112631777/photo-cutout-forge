# 机检口径（两道：构图 checks ＋ 可读性 WCAG）

## 一、构图 checks（auto_compose.py 内置，写入 plan.json）

| 项 | 口径 | 不过怎么办 |
|---|---|---|
| subject×text_zone | 主体覆盖面积占文字区 ≤ 2%（alpha>0.10 判覆盖） | 主体按 0.92 步缩，最多 4 次 |
| backdrop×text_zone | 背景窗覆盖面积占文字区 ≤ 2%（蒙版>0.12 判覆盖） | 背景窗同样步缩（rx/ry×0.92），最多 4 次 |
| blank_ratio | 纸面可见占比 ≥ 0.40（不被主体、背景窗覆盖） | 背景窗再缩（×0.94），最多 6 次 |
| subject_in_canvas | 主体 rect 完整落画 | 回夹位置 |

- checks 全程在 1/4 降采样画布上计算（1500×1875 → 375×469）。
- `plan.json` 的 `checks.pass` 为 false 时脚本返回码 1（可接流程）。

## 二、可读性（check_contrast.py，口径不可改）

- 背景亮度取文字矩形内**单像素 P95（浅字）/ P5（深字）**，非均值；矩形向内收缩 14%（inset）。
- 门槛：字号 ≥ 48px @1500 画布宽 → 大字号 3.0 : 1；其余 4.5 : 1。
- 同时输出 overflowX / overflowY：**必须全 false**（数值不折行、题不出栏）。
- 用法：`--boxes poster.boxes.json --bg poster.bg.png --full poster.png --json report.json`。

### ⚠ 但机检过线 ≠ 视觉上够清楚（2026-10-11 用户反馈后补）

P5/P95 是**保守合规线**（保证"最坏情况也读得出"），**不等于观感**。
材质背景（土墙／岩壁／撕纸）明暗斑驳时，P5 过线了，眼睛看到的仍可能是
「黑字混在深一块浅一块的花底里」——用户原话是「文字颜色与底板材质太相近」。

**`text_contrast.py` 补两个口径**：

| 口径 | 含义 | 判据 |
|---|---|---|
| `cr_p50` | 字色 vs 背景**中位数**（整体观感） | < 3.6 → 视觉上明显不够 |
| `bg_std` | 字框内亮度标准差（底子花不花） | ≥ 26 → 字会糊进纹理 |

```powershell
python scripts\text_contrast.py --bg out\poster.bg.png --boxes out\poster.boxes.json `
    --report out\text-contrast.json [--plate out\bg.png]
```

`--plate` 在文字区做**保色相提亮／压暗**（大半径羽化），生成护读底衬；
覆盖为新的 `bg.png` 后重新渲染即可。

### 护读三件套（按力度递增，先用轻的）

1. **浅色描边**（首选）：`-webkit-text-stroke: 1.8px` ＋ **`paint-order: stroke fill`**
   —— 后者是关键：让描边画在字身**下面**，否则会侵蚀笔画内部、字反而变细。
2. **小字加字重**：中文信息层 sans 用 600；拉丁衬线用 500。
3. **护读底衬**（`text_contrast.py --plate`）：底子特别花时才用，会削弱材质感。

> ⚠️ **加了描边后，QA 仪器里的 `-webkit-text-stroke-color` 必须一起清成 `transparent`。**
> 只清 `color` 的话，浅色描边会留在「无字背景」里被当成背景亮度，
> **机检数值全部虚高**（实测：bgP95 从 150 级跳到 220 级 —— 一眼看不出错，但机检参照已经废了）。

### ⚠ 机检量的是**背景本身**：描边／光晕／字重都不计入

2026-10-12 实测（case17 三面幕墙）：深墨字压在**壁画的暗部**上，P5 只有 22 → CR 2.40 挂。
给字加浅色描边、加发光阴影**对数值毫无帮助** —— `check_contrast` 读的是 `--bg` 那张
"隐去文字墨色与描边"的背景图。
→ 结论：**底子又花又暗时，只能在背景层加「护读底衬」**（`text_contrast.py --plate`，
或案例 `run_case17.py` 里那种柔光纸色 veil：矩形＋大羽化，向纸色混合）。
⚠ 羽化一定要大（本案例 120–220px）——小了会在画面里看见一个**明显的亮/暗矩形**。

#### ⚠⚠ 但底衬**只铺"真的需要"的那一小块，强度取最小值**（2026-10-12 老大反馈后的定论）

第一版我铺了两大块（x60–880 与 x1180–1480，强度 0.46／0.48）→ **把抠出来的图案整体冲淡了**：
老大原话「抠图颜色是原图的样子没有变淡，但**成品却变淡了**，感觉有点糊」。
（对比 `半成品.png` 与成品一眼就能看出。）

正确姿势：

1. **先去掉底衬量一遍**每个文字的 P5，只给**真的不够**的那几个加（本案去底衬后：
   中文标题 93／左缘小标签 94／信息行 108 本身就够；只有压在壁画亮部的**右缘竖排小字** 30–45 不够）；
2. **强度按缺口反推**：深字要 `P5_底 ≥ 0.225`（线亮度），
   `f ≈ (0.225 − P5_底) / (纸色亮度 − P5_底)`；本案约 15–22%，实测取 0.34–0.40；
3. **范围贴着文字收**：只留压着小字的一条（本案 x1150–1500 贴右缘），
   并把文字的框**收进这条带内**（框沿露在带外会被机检抓到亮底 —— EN tagline 4.25 就是这么挂的）。

### 字色：取画面里占比最大的深色（`pick_ink.py`，2026-10-12 加）

固定墨色 `#17130E` 是保底；画面本身有主色调时，**字色取自画面里占比最大的那档深色会更和谐**。
做法：取最暗 `--dark-pct`%（默认 18）像素 → **8×8×8 三维直方图**取最重的几格加权平均
（比直接平均稳，不会被零散噪点拉灰）→ **保底压暗**到 `--max-lum`。

| 要点 | 说明 |
|---|---|
| 取样源 | 取**源场景**，别取成品图 —— 成品里材质的灰调占多数，取出来是灰的（实测 `#86867C`） |
| `--max-lum` 定法 | 按**最苛刻的小字底色**反推：`L_text ≤ (p5_bg + 0.05)/4.5 − 0.05`；本案 p5≈0.23 → ≤0.0125 |
| **必须留余量** | 卡在临界值上会被判挂（实测 0.0125 → CR 4.49，差 0.01）；本案收一档到 **0.011** 才过 |
| 产出 | `ink`（主字色）／`ink2`（提亮 12%，给 tagline 这类次级文字） |

## 三、人目 Gate（机检之外）

1. 候选板：三版背景并排选方向（主体是否突出、背景是否退成「色场」、留白是否够）。
2. `--debug` 图：主体 rect / 背景窗 / 文字区三者位置关系一目了然。
3. 成品：题不被压、印章不压字、副题与短句层级分明、整体留白呼吸感。
4. **★ 四边零「异色窄带」**（2026-10-12 改口径）：**满幅铺底**时照片本身就可能有一整条暗边
   （案例：顶部 144px 是场景的黑色天花板），老的「有暗带就报」会误判。改看**特征**：
   ① 最外 8px 与内侧 60px 的亮度差 > 18 ② 最外 8px 自身 std < 8（是一条"色带"而非画面内容）
   —— 两条同时成立才算漏底色。实现在各 `run_*.py` 的 `edge_report()`。

   
   **机检抓不到这条**——它只看文字矩形，页面底色露出来它也一样判过。

   实测成因（2026-10-10）：`render_png.py` 用 `--headless=new` 时，`--window-size`
   是「**窗口外尺寸**」，实际视口比它小（本机 Edge 135 实测 scale=2 少 21×91 CSS px）。
   截图按 window-size × scale 输出 → 页面只渲染到视口为止 → **右下露出 body 底色**
   （母版 body 是 `#17130E`，就是一条黑边）。深色/撕纸场景最刺眼，
   早期浅纸场景下它也在，只是不易察觉。

   现行 `render_png.py` 已用「加大 window-size 再裁回设计尺寸」修掉。
   若再见到窄带，跑一遍像素审计：四边连续暗带长度应**全为 0**。

   **★ 第二条成因（2026-10-12 修）：母版的 CSS**。背景图原来写 `<img class="art">`，
   与标题艺术字共用 `.art`，而 `.art` 的 `padding:0.15em 0.12em` ＋等量**负 margin**
   （给艺术字 transform 留余量用）会把 `inset:0;width:100%` 的图整体推偏 ≈2.4px →
   **成品右缘／下缘各露 ~5px 的 `--stage-bg`**。五套母版已改 `<img class="bg">`。
   > 判据记牢：**最外 8px 的 `std ≈ 0` = 漏底色**。截图视口漏底与 CSS 推偏，症状完全一样，
   > 但成因一个在渲染、一个在母版 —— 先看「是不是 stage-bg 那个颜色」就能分辨。

5. **★ 文字不压「窗口」（`kraft_window.py` 路线专用）**：这条路线没有「中缝」，
   要改查**文字框与窗口 mask 的重叠面积**（口径：`alpha>128` 判在窗内，重叠 >2% 判压）。
   `run_case16.py` 已内置该检查（遍历 boxes.json × 窗口 mask，逐元素打印重叠百分比）。
   > 横向路线查「不压中缝」，竖向路线查「不压窗口」——**检查项跟着取形走**。
   > ⚠ 但**横向撕口带若也走 `kraft_window`**（见 kraft-tear.md §1.11），检查项跟着**脚本**走：
   > 仍要查「不压窗口」（此时窗口＝那条横带）。

6. **★★ 版面美观底线（2026-10-12 老大定）**：机检与人目 Gate 都过了之后，还要核这三条：

   | 项 | 量化口径 |
   |---|---|
   | **标题要大** | 主标题按「落字区能放多大」定：`字号 ≤ (版心 − 徽标) ÷ (2.8 × 词数)`（sandwich 两词各三字 → 上限 ≈225px） |
   | **不要留白太多** | ① 图像窗／主体**占画面 ≥ 45%**；② 每条纸带里**文字块的上下余白之和 ≤ 文字块自身高度的 1.5 倍** |
   | **整体要美观** | 目检视觉重量分布（标题／小字／信息条／图像／留白），四角不要一角挤满、一角空荡 |

   不达标按「① 改行／改结构 ② 收字号 ③ 调位置」处理——**不许删信息**。
   另：字色／印色要能从素材里找到出处（`pick_ink.py`；素材有暖色时用朱砂方印当落款点）。

7. **★ `giant`（底部裁切超大英文）的 `overflowY` 是预期**：裁切靠容器 `overflow:hidden`，
   被裁掉的字形必然让 scrollHeight 越界 —— 该项由**目检**把关（下半截规整切掉、左右顶满）；
   若出现 `overflowX` 才说明字号超了，回公式重算。

8. **★ 排障判据：`P5 = 0` 而「压窗口」= 0% → 先怀疑元素溢出画布。**
   材质最暗处也有 P5 ≈ 60–80；一旦机检报 **P5 = 0 / CR ≈ 1.14**，而窗口重叠检查却是 0%，
   八成是元素被 flex 推到了**画布外**（落到 body 底色 `#17130E`）。
   ⚠ 这种情况下**元素自身的 `overflowX` 仍是 false**（超宽的是行容器，不是元素），
   所以只有量「元素右缘是否 > 1500」才看得出来。实测：`space-between` 行里两段合计
   817px 塞进 500px 的行 → 第二段跑到 x1618（画布外 118px）→ P5=0、CR 1.14。
   → 处置：**改单列／改行**，别缩字号。

## 四、案例实测（敦煌「壁上万象」）

- 主体 A2（全彩抠图）自动 hero-top；首轮 hero-band 定稿 blank_ratio 0.6472 → pass（历史）。
- 二轮定稿：主体换 A2c（去垂帘重绘，aspect 1.60）＋青金浅纸＋投影 0.30／倒影 0.18（投影/倒影不参与 checks，人目 Gate 把关）：
  subject×zone 0.0 ／ backdrop×zone 0.0 ／ blank_ratio 0.7153 ／ 落画 true → pass。
  成品 12/12 全过（主标题 11.28、最小 presenter 5.63），overflow 全 false。
- 迭代教训：蓝灰取景 lens 背景窗读成「光斑」→ 去窗／满幅才消解；垂帘遮挡主体 → 图生图编辑去除再重抠；
  倒影 0.30 以下肉眼近乎不可见（可见档 ≈0.50）。

### 案例 05（2026-10-12，弧形灯箱照片墙 ＋ 青海波纹样纸 · 文化活动主视觉）

- 路线：横向撕口带，但**窗口脚本用 `kraft_window.py`**（横向选景排掉照片左侧的巨型鎏金主面板）：
  `band_mask --orient h`（带高 ≈0.458H）→ `torn_edge --edge 0.017 --bites 0 --fray 0.60`
  → `kraft_window --material-gain 1.0 --detail 2.0 --scale 1.0 --focus 0.56856,0.38531`。
- 机检：中英各 **10/10 全过**（最低 10.25，大字号 3.0 门槛下主标题 15.15）；overflow 全 false。
- 人目 Gate：四边审计**最外 8px std 均 > 0.02、与内侧 60px 的差最大 0.19 但 std 不为 0 → 无漏底**；
  文字压窗 **0.00%**（窗口上缘 min 487，标题块底 404；窗口下缘 max 1445，信息块顶 1580）。
- 版面美观底线三项均达标：主标题 208px（上限 ≈225）、图像窗覆盖 **47.2%**、
  顶栏与底栏的文字块余白分别约 0.54×／1.31× 自身高度。

## 五、排障（不达标常见成因）

| 症状 | 处理（先位置后墨色） |
|---|---|
| 文字压到背景窗/主体 | 调版式 CSS 位置或 `--subject-target`／`--bd-zoom` 缩背景；复跑 auto_compose 的 checks |
| 数值折行（overflowX） | `.meta` 不设百分比宽度；栏宽不够先缩字号 |
| 浅字对比不足 | 背景窗 `--wash` 加大（更褪色）或主体/窗下移；最后才调墨色 |
| 留白不足 | 缩主体 target、缩背景窗 rx/ry |
| **成品四边有异色窄带** | 渲染视口补偿失效：增大 `render_png.py` 的 `PAD`（`--headless=new` 的 `--window-size` 只框窗口、视口更小，页面底部/右侧会露 body 底色） |
